# Табель учёта рабочего времени — вариант 3

Учебный проект для первой аттестации по ООП. Модель находится в `src/main/java/ru/vsu/oop/timesheet`, консольная демонстрация — `Demo`, тесты — в `src/test/java`. Данные хранятся только в памяти.

## Что умеет базовый уровень

1. Регистрирует сотрудников и смены; не допускает пересекающиеся смены одного сотрудника.
2. Делит смену на однородные отрезки по границам **06:00**, **22:00** и календарных суток.
3. Вычисляет отработанную `Duration` за произвольный период `[начало, конец)`.
4. Формирует месячный отчёт по четырём видам времени и считает оплату в копейках.
5. Выдаёт понятное `TimesheetException` при повторном номере сотрудника, неизвестном сотруднике или пересечении смен. Консольный пример показывает обработку исключения.

`EmployeeId` — неизменяемый `record` с корректными `equals/hashCode`; `Employee` и `Shift` тоже неизменяемы. Закрытая иерархия `WorkPeriod` объединяет смену и классифицированный отрезок и полиморфно вычисляет `duration()`. `TimeType` реализует `PayPolicy`; коэффициент определяется в теле каждой константы перечисления. `Timesheet` копирует переданный набор праздников и не выдаёт наружу изменяемые внутренние коллекции.

## Правила расчёта

| Вид | Условие | Коэффициент |
| --- | --- | ---: |
| Обычное | Остальное время | 1,0 |
| Ночное | 22:00–06:00 | 1,2 |
| Сверхурочное | Смена помечена `overtime=true` | 1,5 |
| Праздничное | Дата задана в наборе праздников | 2,0 |

Интервалы **взаимоисключающие**. Если условия совпали, порядок приоритета: праздничное, сверхурочное, ночное, обычное. Например, час ночью в праздничный день учитывается один раз как праздничный с коэффициентом 2,0. Коэффициенты — правила *этой учебной модели*, а не расчёт по трудовому законодательству. Пометка сверхурочной смены задаётся при её создании; автоматическое сравнение с нормой часов относится к повышенному уровню.

Смена задаётся двумя `LocalDateTime` с точностью до минуты. Конец должен быть строго позже начала; для смены через полночь указываются разные даты. Границы интервалов полуоткрытые, поэтому час ровно с 22:00 считается ночным, а с 06:00 — обычным. Отчёт берёт только часть смены внутри выбранного месяца. Оплата каждого классифицированного отрезка: `ставка_в_копейках × коэффициент × минуты / 60`, округление `HALF_UP` до целой копейки; затем суммы складываются. Для работы в ночь перевода часов и контроля нормы часов нужен повышенный уровень на `ZonedDateTime`; в эту реализацию он не входит.

## Запуск

Требуются **JDK 21** и **Maven**.

```bash
mvn clean verify
java -cp target/classes ru.vsu.oop.timesheet.Demo
mvn javadoc:javadoc
```

Документация появится в `target/reports/apidocs` (при вызове цели `javadoc:javadoc` обычно `target/reports/apidocs`); если используется другая конфигурация Maven, путь показывает вывод команды.

Демонстрация создаёт **8 сотрудников и 32 смены** (всего 40 исходных объектов), показывает разбиение, полиморфный метод, время за период, месячные итоги, коэффициенты и обработку пересечения смен. 14 сентября 2026 года в примере задано **условным** праздником.

## Проверки

`TimesheetTest` содержит 17 сценариев: контракт идентификатора, некорректные данные, границы ночи и месяца, смена через полночь, приоритет типов, точность оплаты, пустой отчёт, копирование коллекций и осмысленные исключения. Тесты запускаются командой `mvn test` либо вместе со сборкой через `mvn clean verify`.
