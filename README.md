# Табель учёта рабочего времени — вариант 3

Учебный проект для первой аттестации по ООП: базовый и повышенный уровни варианта 3. Модель находится в `src/main/java/ru/vsu/oop/timesheet`, консольная демонстрация — `Demo`, тесты — в `src/test/java`. Данные хранятся только в памяти.

## Что умеет базовый уровень

1. Регистрирует сотрудников и смены; не допускает пересекающиеся смены одного сотрудника.
2. Делит смену на однородные отрезки по границам **06:00**, **22:00** и календарных суток.
3. Вычисляет отработанную `Duration` за произвольный период `[начало, конец)`.
4. Формирует месячный отчёт по четырём видам времени и считает оплату в копейках.
5. Выдаёт понятное `TimesheetException` при повторном номере сотрудника, неизвестном сотруднике или пересечении смен. Консольный пример показывает обработку исключения.

`EmployeeId` — неизменяемый `record` с корректными `equals/hashCode`; `Employee` и `Shift` тоже неизменяемы. Закрытая иерархия `WorkPeriod` объединяет смену и классифицированный отрезок и полиморфно вычисляет `duration()`. `TimeType` реализует `PayPolicy`; коэффициент определяется в теле каждой константы перечисления. `Timesheet` копирует переданный набор праздников и не выдаёт наружу изменяемые внутренние коллекции.

## Правила расчёта

| Вид | Условие | Коэффициент |
| --- | --- | ---: |
| Обычное | Остальное время | 1,0 |
| Ночное | 22:00–06:00 | 1,2 |
| Сверхурочное | Смена помечена `overtime=true` | 1,5 |
| Праздничное | Дата задана в наборе праздников | 2,0 |

Интервалы **взаимоисключающие**. Если условия совпали, порядок приоритета: праздничное, сверхурочное, ночное, обычное. Например, час ночью в праздничный день учитывается один раз как праздничный с коэффициентом 2,0. Коэффициенты — правила *этой учебной модели*, а не расчёт по трудовому законодательству. Пометка сверхурочной смены задаётся при её создании; автоматическое сравнение с нормой часов относится к повышенному уровню.

Смена базового уровня задаётся двумя `LocalDateTime` с точностью до минуты. Конец должен быть строго позже начала; для смены через полночь указываются разные даты. Границы интервалов полуоткрытые, поэтому час ровно с 22:00 считается ночным, а с 06:00 — обычным. Отчёт берёт только часть смены внутри выбранного месяца. Оплата каждого классифицированного отрезка: `ставка_в_копейках × коэффициент × минуты / 60`, округление `HALF_UP` до целой копейки; затем суммы складываются.

## Повышенный уровень

`ZonedShift` и `ZonedTimesheet` работают с `ZonedDateTime`. Часовой пояс задан для отдельного табеля сотрудника. При переходе на летнее время пропущенный час **не учитывается**, а при обратном переводе повторяющийся час **учитывается дважды**: берётся действительное время между моментами, а не разность надписей на часах. Ночь с 22:00 до 06:00 в `Europe/Berlin` длится 7 фактических часов при весеннем переходе 29 марта 2026 года и 9 часов при осеннем переходе 25 октября 2026 года. Время праздников определяется по местной дате часового пояса. Классификация и коэффициенты совпадают с базовым уровнем.

При создании `ZonedTimesheet` задаются месячная норма и допустимая переработка как `Duration`. Перед записью смены проверяется фактическое суммарное время **каждого затронутого месяца**: оно не должно превышать `норма + разрешённая переработка`. При превышении выбрасывается `OvertimeLimitException`, смена не записывается. Смены одного сотрудника не могут пересекаться, включая повторяющийся час при осеннем переводе. Норма одинакова для каждого месяца этого учебного примера; если нужен производственный календарь с разными месячными нормами, модель потребуется расширить.

## Запуск

Требуются **JDK 21** и **Maven**.

```bash
mvn clean verify
java -cp target/classes ru.vsu.oop.timesheet.Demo
mvn javadoc:javadoc
```

Документация появится в `target/reports/apidocs` (при вызове цели `javadoc:javadoc` обычно `target/reports/apidocs`); если используется другая конфигурация Maven, путь показывает вывод команды.

Демонстрация создаёт **8 сотрудников и 32 смены** (всего 40 исходных объектов) для базового уровня, показывает разбиение, полиморфный метод, время за период, месячные итоги, коэффициенты и обработку пересечения смен. Дополнительно показывает весенний и осенний переход времени, отчёты по ним и отказ в записи смены сверх лимита. 14 сентября 2026 года в базовом примере задано **условным** праздником.

## Проверки

`TimesheetTest` содержит 17 сценариев: контракт идентификатора, некорректные данные, границы ночи и месяца, смена через полночь, приоритет типов, точность оплаты, пустой отчёт, копирование коллекций и осмысленные исключения. `ZonedTimesheetTest` добавляет 12 сценариев: оба перехода часов, граничный лимит и отказ без изменения данных, месяцы на границе, конфликты смен, копирование набора праздников. Всего **29 тестов**. Запуск: `mvn test` либо `mvn clean verify`.
